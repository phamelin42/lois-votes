# Prompt 14 : icône du site (onglet du navigateur et résultats Google)

Branche : `lv/14-icone`, créée depuis `claude/bold-fermi-zihw5t` (`git fetch origin && git checkout -b lv/14-icone origin/claude/bold-fermi-zihw5t`).

## Contexte commun

Dépôt `phamelin42/lois-votes`, site « Qui a voté quoi ? » (`quiavotequoi.phamelin.fr`), 17ᵉ législature, en production sur Vercel. Lis `docs/PLAN.md`, `CLAUDE.md` (dont « Serveur et déploiement » et « Budgets ») avant de commencer.

Règles : textes et commits en français, ne modifie pas Fuda. Node 24 : `export PATH=/root/.local/node/node-v24.22.0-linux-x64/bin:$PATH` à chaque commande ; `npm ci` d'abord. Chromium dans `/opt/pw-browsers` (jamais `playwright install` ; `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome` si besoin). Ne tue pas de processus avec `pkill -f` (récupère le PID avec `ps`). Pas de pull request ; ne pousse que ta branche. **Aucune nouvelle dépendance** : npm 11 bloque les scripts d'installation (donc `sharp` ne s'installe pas correctement) ; utilise ce qui est déjà là.

## La demande de l'utilisateur

« Ajoute une icône à l'onglet et à la recherche Google. » Le site n'en a aucune aujourd'hui : `src/index.html` n'a pas de `<link rel="icon">`, il n'y a pas de dossier `public/` et `angular.json` a `"assets": []`.

## Ce que Google demande

Lis la page officielle **`https://developers.google.com/search/docs/appearance/favicon-in-search`** (récupère-la avec `curl -L` ; sa version courante fait foi) et applique-la. D'après des sources secondaires : icône **carrée**, **8×8 au minimum et 48×48 recommandé**, déclarée par `<link rel="icon">` dans l'en-tête de la **page d'accueil**, adresse **stable**, **explorable** par Googlebot et Googlebot-Image (`robots.txt` du site autorise déjà tout : ne rien y bloquer), un seul favicon par site. L'affichage dans les résultats peut prendre des jours ou des semaines et n'est pas garanti : ne promets rien d'autre dans la documentation. Ne dis jamais « multiple de 48 » : ce n'est pas confirmé.

## Travail

1. **Dessin** : un fichier SVG dans l'identité de Fuda (le design system s'inspire du hanafuda, « fuda » = la carte) : une **carte arrondie** couleur `sakura` avec liseré d'encre (`rim`) et un motif simple, gras, **lisible à 16 px** (par exemple une coche de vote). Pas de trait fin, pas de texte. Relève les couleurs dans les tokens de Fuda (`node_modules/fuda/styles/tokens.css`, thème Jour) : les littéraux hexadécimaux sont autorisés dans ce fichier statique (le contrôle « aucune valeur en dur » ne porte que sur les `.scss`), mais documente la correspondance token → valeur dans `docs/ICONE.md`. Le dessin doit rester lisible sur un onglet clair et sur un onglet sombre grâce à son propre fond et à son contour (pas de `prefers-color-scheme` dans le SVG).
2. **Fichiers** dans `public/` (copiés à la racine du build ; configure `angular.json` : `assets` avec `{ "glob": "**/*", "input": "public" }`) : `favicon.svg`, `favicon.ico` (entrées 16, 32 et 48 px), `apple-touch-icon.png` (180 px), `icon-192.png`, `icon-512.png`, `site.webmanifest` (nom, nom court, `lang: fr`, couleurs, icônes). Ajoute `icon-48.png` si tu juges utile de l'exposer à Google en plus de l'ICO.
3. **Génération reproductible** : `scripts/icones.mjs` (`npm run icones`) : rastérise le SVG en PNG avec le **Chromium de Playwright** déjà installé et écrit l'ICO (conteneur ICO dont les entrées sont des PNG, écrit à la main : en-tête, répertoire, données). Les fichiers générés sont **commités** (le build Vercel ne génère rien). Le script est déterministe (deux exécutions donnent les mêmes octets, ou dis pourquoi non).
4. **`src/index.html`** : `<link rel="icon" href="/favicon.ico" sizes="48x48">`, `<link rel="icon" href="/favicon.svg" type="image/svg+xml" sizes="any">`, `<link rel="apple-touch-icon" href="/apple-touch-icon.png">`, `<link rel="manifest" href="/site.webmanifest">` et `<meta name="theme-color" content="…">` (valeur du token `sakura`, une seule). Vérifie qu'elles sont dans le HTML **rendu par le serveur** de `/` (c'est ce que lit Google).
5. **Service des fichiers** (`src/server.ts`, `src/server/en-tetes.ts`, `vercel.json`, `api/index.mjs`) : ces fichiers sont à la racine et **non hachés** : ils ne doivent **pas** hériter du `Cache-Control: public, max-age=31536000, immutable` des fichiers du build ; donne-leur `public, max-age=86400`. Vérifie en local **et** dans la configuration Vercel (la réécriture `/(.*)` vers la fonction ne doit pas empêcher `/favicon.ico` et les autres d'être servis avec le bon `Content-Type` : `image/x-icon` ou `image/vnd.microsoft.icon`, `image/svg+xml`, `image/png`, `application/manifest+json`). La CSP (`en-tetes.ts`) ne doit pas les bloquer. Le sitemap et `robots.txt` ne changent pas.
6. **Tests** : spec Vitest (en-tête et répertoire de l'ICO, tailles 16/32/48, signatures PNG, dimensions des PNG, JSON du manifeste valide et icônes qui existent, fichiers cités par `index.html` présents dans `public/`) ; e2e Playwright (chaque URL répond 200 avec le bon `Content-Type` et le bon `Cache-Control` ; les `<link>` sont dans le HTML de `/` **JavaScript désactivé** ; `/favicon.ico` n'est pas capturé par la route 404 de l'application). Ajoute-les aux specs existantes (`e2e/ssr.spec.ts`) ou à un fichier dédié.
7. **Vérification visuelle** : affiche le SVG et les PNG à 16, 32, 48 et 180 px sur fond clair et fond sombre, décris ce que tu vois (lisibilité de la coche à 16 px) et dis si tu as dû simplifier le dessin ; joins les images hors dépôt si tu peux.
8. **Docs** : `docs/ICONE.md` (dessin, correspondance des couleurs, commande de génération, exigences de Google et lien officiel, ce qui est garanti et ce qui ne l'est pas) ; `README.md` : le geste de l'utilisateur **après le déploiement** : demander la réindexation de la page d'accueil dans Google Search Console, et patienter ; `CLAUDE.md` : fichiers de `public/`, commande `npm run icones`, règle de cache.

## Terminé quand

`npm run lint`, `typecheck`, `test`, `build:fixtures` et `npm run e2e` sont verts (axe sans violation). `npm run build` (réel, réseau permettant) puis `npm run serve:ssr` : `curl -sI localhost:<port>/favicon.ico` et `/favicon.svg`, `/apple-touch-icon.png`, `/site.webmanifest` répondent 200 avec le bon type et le bon cache ; `curl -s localhost:<port>/ | grep -i "rel=\"icon\""` montre les balises. Rapport : ce qui est fait, valeurs contrôlées, résultat de la lecture de la page officielle de Google (ce qu'elle dit vraiment aujourd'hui), vérification visuelle, écarts, ce qui n'a pas pu être fait. Commits en français, `git push -u origin lv/14-icone`.
